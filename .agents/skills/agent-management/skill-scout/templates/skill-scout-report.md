# スキル見直し

必要な項目だけを使う。短い依頼はチャットの箇条書きで足りる。

## 対象と根拠

判断したい問い、対象skill、モデル、runtime、比較した版、確認した入力や文書を示す。
変更によって何が改善するはずかを具体的な挙動で示す。
ソースの点検、保存済み成果物の評価、新規実測のどれを行ったかを区別する。

## 優先する変更

| 対象箇所 | 観測した問題 | 最小の対処 | 残す契約 | 確認方法 |
|---|---|---|---|---|

削除、適用条件の限定、参照分離、統合、維持から、根拠に合う対処を選ぶ。
installed skillはupstream更新や別名wrapperとして記載する。

## 検証と未確定事項

実施した確認と結果、確認できなかった範囲を示す。
採否は比較した版、採点者、判断理由と根拠を伴う場合だけ記載し、静的検査だけなら効果は未実証とする。
同じ入力に対する変更前後の成果物へリンクする。
比較実験では `skill-loop.py report <round>` が生成するreport.mdを参照し、plan、review、decisionの内容を手で重複管理しない。
見直しメモは提案、生成report.mdは保存済み証拠の説明、decision.jsonは判断の正本として扱う。
外部資料には出典と、このrepositoryへ適用する理由を添える。

## 次の作業

実施済みの変更と残件を分け、既存の依頼範囲で進める作業を示す。
追加情報や未承認の操作が必要な場合だけ、対象と理由を具体的に記す。
