# 返信方針

レビューコメントへ返信するときに読む。

## 基本方針

原則として 1 review comment に対して 1 reply を対応させる。
commit は追跡しやすい単位にする。
複数コメントが同じ原因を指している場合や、既存 commit を amend するほうが自然な場合は、1 commit にまとめてよい。
返信では次を明確にする。

- 何を変更したか
- なぜその変更で指摘に対応できるか
- 対応 commit
- あえて変更しなかった点がある場合はその理由
- 何を検証したか

コメントに補足説明、詳細欄、自動レビューの追加観点などが含まれる場合は、それらも同じ指摘の一部として読み、返信前に対応漏れがないか確認する。

## 自動生成したインラインレビューコメント

AI レビューア（Codex/GPT、Claude など）が作成した指摘を PR のインラインコメントとして投稿するときは、本文を次の 2 層にする。

1. `<details>` の上には、人間が展開せずに読める補足コメントを置く。ユーザーから人間のコメントを指定された場合はそれをそのまま使い、指定がない場合は指摘の要点・影響・修正方針を 1〜2 文で要約する。
2. 再現条件、根拠、詳しい影響、具体的な修正案、追加すべきテストなどは `<details>` 内へ入れる。
3. 詳細欄の末尾には、その指摘を実際に作成したモデル名を `by <model>` の形で置く（例: `by Codex`、`by Claude`）。`<details>` の上にある人間向けコメントには付けない。
4. ユーザーが draft / pending を指定した場合は、コメントを pending review に追加するだけにして `Submit review` は実行しない。

```html
{{human_comment_or_summary}}

<details><summary>Details</summary>
<p>
{{detailed_finding}}

by {{model}}
</p>
</details>
```

標準の返信文は `templates/review-reply.md` を構造として使う。
