# 実験レポートSiteで避ける失敗

## 結果を見てから実験条件を決める

**症状**：改善したケースに合わせて採用基準や指標を後付けし、事前の仮説に見せる。

**対処**：実験契約を先に保存する。事後に追加した分析と閾値は区別する。

## 比較対象を相対名だけで示す

**症状**：「main」「旧版」「現在」が、どのcommitやdeploymentか分からない。

**対処**：不変のvariant IDとsource revisionを記録し、相対名は表示用に限る。

## 固定条件を変えて同じrunを上書きする

**症状**：fixtureやfont sizeを変更した後も、変更前の結果と同じ実験として集計する。

**対処**：固定条件が変わったらrun IDを分け、旧成果物を残す。

## レポートへ結果を手入力する

**症状**：HTMLの表、画像名、生データの値がずれ、再実行しても更新されない。

**対処**：機械可読なケース別resultから表、集計、captionを生成する。

## 平均値だけで採用を決める

**症状**：平均は改善しているが、未解決や大幅な悪化が隠れる。

**対処**：分布、最悪値、未解決、悪化ケースを併記し、棄却条件を適用する。

## 時間の意味が決まっていない

**症状**：「計算時間」に外部I/Oや画像保存が含まれるか分からず、値を比較できない。

**対処**：clock、開始点、終了点、反復、warm-up、集計方法を指標定義へ入れる。

## 終了段階を画像から推測する

**症状**：見た目から`font_shrink`などのphase名を付け、実行経路と食い違う。

**対処**：実装またはハーネスが出力した終了理由をresultへ保存する。表示名は説明用の日本語と内部IDを対応づける。

## 成功画像だけを載せる

**症状**：代表例だけが並び、全ケースの変化、未解決、品質劣化を確認できない。

**対処**：全ケースの入力、基準、候補を同じ縮尺で並べ、フィルターは表示補助として追加する。

## 一つより多い条件を同時に変える

**症状**：ロジックとfixture、renderer、設定が同時に変わり、差の原因を特定できない。

**対処**：意図した操作変数以外を固定する。固定できない差は交絡要因として記録する。

## 成果物とSiteの版がずれる

**症状**：別runのJSON、画像、説明が一つのSiteに混ざる。

**対処**：run IDとvariant IDで成果物を結び、生成時に欠損と重複を検査する。
