# 今日の整理

Codex で実行する場合は、pinned されたCodexタスクを日次確認の基本候補として扱う。
pinned は候補集合を示すだけで、優先度、未完了、作業状態の根拠にはしない。
必要に応じて、ユーザーが明示した外部のタスク管理ツールや会話記録を追加する。
参照できない情報は補完せず、「不明」と書く。

## Codexでの候補選定

1. 利用可能な thread tool で pinned task を取得する。
2. 各 pinned task の直近の会話、明示された次の一手、完了報告と、未完了一覧の記録を照合する。
3. 未完了と判断できる pinned task を、日次確認用に次のどちらかへ分類する。
   - **doing**：着手済みで、未完了の作業または次の一手が確認できる。
   - **pending**：未着手、保留、判断待ち、外部待ちのいずれかである。
4. `active`、`idle`、`notLoaded` はCodexの実行状態として併記できるが、doing / pending や完了の根拠にはしない。
5. 根拠が足りないものは推測で二分類せず「要確認」にする。完了が明記されたものは完了候補として分ける。
6. unpinned task は、ユーザーが指定した場合、または未完了一覧に残っていて整合確認が必要な場合だけ別枠で確認する。最近更新されたという理由だけで基本候補へ加えない。

doing / pending は日次確認用の分類であり、未完了一覧の状態語彙を置き換えない。
分類案を一覧にしてユーザーへ一度に確認し、確認前に正本や日次ログへ確定状態として書き込まない。

## 集約

1. Codexでは pinned task を集める。ほかの環境では、未完了またはユーザーが指定したタスクを集める。
2. 各タスクから目的、現在地、次の一手、期限または依存関係を抽出する。
3. 重複する作業は一つに束ねる。
4. 情報が古い、または判断に足りないタスクは「要確認」に分ける。

外部の正本がある場合は、Codexの要約より正本を優先する。
外部情報をまだ接続していない場合は、Codex内の情報だけで整理したことを明記する。

## タスク一覧の保管

未完了タスクは、作業リポジトリとは別のタスク管理ディレクトリに置く Markdown 一覧を正本にする。
一覧には、タスク名、状態、次の一手、関連するタスクスレッドを書く。
日ごとの優先順位と状態変更は、同じディレクトリの `daily/` に日付ごとに記録する。
調査、実装、詳細な議論は関連タスクスレッドに残す。

日次整理の開始時は一覧を読み、Codexでは pinned task との一致と差分を確認する。
実行状態が `idle` であることを完了の根拠にしない。
ユーザーが優先順位や次の一手を決めたら、一覧と当日の日次ログを更新する。
完了は、ユーザーまたは関連タスクスレッドで完了が確認できた場合だけ一覧から外す。

## 出力

初回確認では、pinned task を **doing**、**pending**、**要確認**、**完了候補** に分け、根拠を短く添えて認識が合っているか一問で確認する。
分類が確認できた後は、次の順序を守る。

1. **日付**：ユーザーのローカル日付を書く。
2. **今日の焦点**：一文。
3. **優先3件**：各項目に、目的、次の一手、完了条件を一文ずつ書く。
4. **保留・待ち**：着手しない理由または待ち先を書く。
5. **判断待ち**：ユーザーの決定が必要なことだけを書く。
6. **確認する一問**：優先順位を決めるための質問を一つだけ置く。

候補が三件未満なら、無理に補わない。
すでに優先順位が決まっている場合は、質問ではなく実行順を確認する。

## 更新

予定が変わったときは、優先3件だけを更新する。
終業前は、完了、継続、保留を区別し、翌日の最初の一手を一つ決める。

## 読み上げ

詳細な整理の後に、30秒程度の**読み上げ用要約**を付ける。
日付、今日の焦点、最優先の一件、ユーザーに必要な判断を自然な話し言葉で二文から四文にまとめる。
優先3件の詳細、保留項目、期限が不明な情報は読み上げない。
ユーザーが「詳しく」と言ったときだけ、対応する項目を読む。

## 音声での運用

音声会話から「今日の整理」を求められた場合、詳細な整理は日次整理の保管先へ追記する。
会話では、読み上げ用要約だけを返す。
保管先の詳細をそのまま読み上げない。
ユーザーが優先順位を決めた後は、決定内容と次の一手を保管先へ追記し、音声では決定だけを短く確認する。
