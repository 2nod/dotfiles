# ローカル Notion の保存判断

ローカル Notion は、複数の正本を横断して現在の理解や反復利用する運用知識を得るために使う。
実装履歴や一回限りの実行証跡を集積する場所にはしない。

## 情報の置き場所

| 情報 | 置き場所 |
| --- | --- |
| API契約、設計判断、安定した処理フロー | repositoryのDesign、ADR、API文書、実装近傍の文書 |
| 変更履歴、PR単位の検証結果、CI結果、job ID、deploy tag | PR、CI、実行ログ |
| 複数repositoryを横断する現在の理解、正本への案内、反復利用する運用知識 | ローカル Notion |
| 実装中の進捗、調査メモ、未採用案 | `docs/plans`などの一時文書 |

## 保存条件

ユーザーが記録を明示的に求めた場合を除き、次の条件をすべて満たす知識だけをローカル Notionへ残す。

1. 現在のPRやdeployが終わった後も、複数の作業で参照する。
2. 一回の実行履歴ではなく、現在の仕様、判断、運用を説明する。
3. repository内に適切な正本がないか、複数の正本を横断しないと理解できない。
4. 何が変わったときに更新または削除するかを説明できる。

repositoryに正本がある場合は、ローカル Notionへ全文を複製しない。
必要なら正本へのリンクと、横断して理解するための要約だけを残す。

## 保存しない情報

- PR別の検証レポート。
- job ID、実行時間、deploy tagなど、一回限りの実行値。
- dev環境で一度だけ確認した正常系や一時的な環境状態。
- PR、CI、ログから再取得できる変更履歴や実行証跡。
- Design、ADR、API文書の全文コピー。
- 実装中だけ必要なplan、レビュー対応メモ、調査途中の断片。

これらに含まれる知識が保存条件を満たす場合は、実行証跡ごと保存せず、現在も有効な契約や運用だけを既存文書へ反映する。

## 例外

次は履歴自体が成果物になるため、独立文書として残してよい。

- 再発防止に使う障害postmortem。
- 繰り返し実行する検証runbook。
- 保存義務がある監査証跡。
- ユーザーが保存を明示した決定記録や検証記録。

例外として残す場合も、観測日、適用範囲、正本へのリンク、更新または廃止条件を記載する。

## 終了時の確認

次の順に判断する。

1. repositoryの正本へ置くべき情報は正本へ移す。
2. PR、CI、ログに残る実行証跡はローカル Notionへ複製しない。
3. 保存条件を満たす横断知識だけを既存文書へ反映する。
4. 残った一時文書と重複文書を削除する。
